# Shared HTTP status recovery

Target: `src/components/status/StatusPage.tsx`, rendered by `apps/marketing/src/layouts/StatusDocument.astro` and the React error boundary. Mode: Operate. This extends the prior public 404 surface into one config-driven status system while preserving the existing marketing visual identity and static-host 404 contract.

## Direction contract
THESIS: A recognizable status and a clear next step, expressed through one oversized typographic code. Friendly, specific recovery copy carries the task; technical reasons and pathname remain supporting context.
OWN-WORLD: Preserve the existing mineral-mint, forest-ink and emerald palette, self-hosted Manrope, system monospace for paths, softly squared controls, stroke icons and ruled navigation. Scoped dark mode reassigns the existing code-plane colors to the same semantic roles; it is an extension of the incumbent world, not a new palette or site-wide theme.
STORY: Understand what happened and choose a useful next action. The five HTTP classes share one layout but receive class-specific copy, central-digit accents and restrained motifs. Home and safe same-site history remain available; errors can lead to studio, docs, features and contact. Display only the requested pathname, safely, without query parameters.
FIRST VIEWPORT: Compact brand header, centered oversized status code and fine directional motif, one heading, short explanation, primary and secondary recovery actions, then a quieter hint and reason. Class 4 adds familiar destinations; the footer anchors the viewport. Actions and ruled destination rows stack on narrow phones.
FORM: Direct code-led extension of the pinned existing style; no new font, color, icon family or identity. Processing breathes, success briefly reveals a check, redirects move a directional arrow, client errors retain the eight-second drifting center digit, and server failures breathe a signal motif. Entrance stagger completes within 760ms. Motion uses transform/opacity; reduced motion makes these effects static while controls and timers remain usable.
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

The existing `DESIGN.md` and `.impeccable/design.json` remain authoritative and preserved. The dark-role mapping and status motion are scoped surface extensions, including an explicit exception to the global Still Surface Rule. No shipping raster or dependency is introduced. Verify light/dark at 360px, 768px and 1280px or wider, real HTTP error statuses and noindex, safe history fallback, keyboard focus, reduced motion, overflow, bounded/cancellable timers and production exclusion of dev demonstrations.

## Implementation documentation
- `src/components/status/StatusPage.tsx` is the single UI. `status-config.ts` owns 35 requested entries and five class defaults: 100, 101, 102, 103; 200, 201, 202, 204, 206; 300, 301, 302, 304, 307, 308; 400, 401, 403, 404, 405, 408, 409, 410, 413, 414, 415, 418, 422, 429, 451; 500, 501, 502, 503, 504. An unknown valid code keeps its number and uses class copy; invalid input becomes 500. Config controls reasons, titles, messages, hints, CTAs, motif variants and accent roles; adding an entry updates the sorted gallery and error-document generation.
- `status-page.css` scopes the existing palette and Manrope to `.status-page`, so host application variables do not recolor recovery and recovery does not retheme the IDE. Light roles reuse the marketing canvas, text and emerald family. Dark roles use Ink Code for the canvas, Forest Ink/Code Rule for surfaces, Mint Code for primary text and filled actions, Code Ghost for secondary text and links, Code Muted for metadata, Code Panel for display numerals and Code Dim for borders. Existing secondary foliage supplies the dark divider. No new token values are promoted into the global design system.
- The compact GB mark retains the existing 34px badge and 9px corner; status recovery controls use the documented 6px corner and a 48px minimum height. Icons use the marketing registry's 24×24 geometry, 1.75px stroke and inherited color. Numeral composition, ruled destinations, theme roles and motion are local extensions. Pre-existing drift remains: shared `.ui-button` CSS uses 8px corners while the design documents specify 6px, and global error typography describes the earlier page. This change does not repair that drift.
- Recovery routes connect Home to `/`, studio to `/app/projects`, docs to `/docs`, features to `/features`, support to `/contact` and the footer's page index to `/sitemap`. The user-approved 401 default leads to Contact for sign-in help until an auth route exists; `loginHref` can supply a real local sign-in target. 403 offers Go back and Contact. Server errors offer Retry and Contact, with Home retained. Go back uses same-origin referrer/history evidence and otherwise follows its home fallback.
- `status-client.ts` supplies the same controller to static Astro markup and React. Pathnames enter through `textContent`. Redirect targets accept local absolute paths only. Redirect countdowns and 503/504 automatic retries require explicit props; both have Cancel and manual recovery. Retry attempts use session storage, exponential backoff and a default cap of three; failed persistence stops automatic reloads. 429 waits before enabling manual Retry without automatically requesting again. Live regions announce timer state. React unmount removes listeners, timers and owned metadata.
- `/404.html` comes from `apps/marketing/src/pages/404.astro` through `StatusDocument.astro`; the wrapper supplies title, viewport, description and noindex. Astro remains static and renders React markup without React hydration, then mounts the small shared controller. Static hosting must return that document with HTTP 404 for an unknown marketing route; there is no catch-all 200 rewrite.
- The build-only `/_status-documents/[code]` route renders the 20 configured 4xx/5xx documents. `scripts/pack-status-documents.mjs` packs these into ignored `api/_lib/status-pages.generated.cjs` and removes the temporary public directory. `api/_lib/status-response.cjs` sends real error statuses with noindex/no-store; unknown runtime error codes normalize to a generic 400/500 document and status. Marketing must be rebuilt after config or UI changes so the server documents and `_astro` assets match.
- Browser HTML errors from the preview API use these packed documents; JSON consumers retain their contract. Node API dispatch, the Vite API dev hook and the combined preview server use the shared 500 for caught browser-request failures. Astro dev SSR middleware rewrites thrown rendering failures to the dev 500 response. Platform-generated failures outside those handlers remain under platform control. The React boundary displays this same 500 UI, preserves emergency-backup export and includes collapsed developer details only in development. A browser boundary cannot change an HTTP status already sent.
- The dev gallery lives in `apps/marketing/src/dev`, outside production pages. `astro.config.mjs` injects `/__status`, `/__status/[code]`, `/__status/error/[code]` and `/__status/throw` only for dev. The main gallery groups all 35 codes by class with code/theme selectors and opt-in countdown demos (`?timer=on`); `?theme=light` and `?theme=dark` select explicit themes. Demonstrations return HTTP 200, including informational, no-content and redirect designs. Real error demonstrations use `/__status/error/429` (with Retry-After) or `/__status/throw` (caught HTTP 500). No gallery, throw route, informational/success/redirect document or developer trace belongs in production output or the sitemap.
- `src/components/status/README.md` records integration props, dev entry points, server behavior and validation commands. Source inspection establishes these implementation relationships; it does not certify rendered accessibility, browser behavior, deployed-host responses or completion of the current finish pass.
